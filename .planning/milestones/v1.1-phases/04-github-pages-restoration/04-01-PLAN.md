  <action>
Create `.github/workflows/deploy-docs.yml` with the following exact content. This is the workflow recovered from the deleted commit e2026848, with action versions verified current by the research phase.

The workflow has two jobs: `build` (builds Jekyll site from docs/) and `deploy` (deploys the artifact to GitHub Pages).

```yaml
name: Deploy Documentation to GitHub Pages

on:
  push:
    branches:
      - main
    paths:
      - 'docs/**'
      - '.github/workflows/deploy-docs.yml'
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Pages
        uses: actions/configure-pages@v5

      - name: Build with Jekyll
        uses: actions/jekyll-build-pages@v1
        with:
          source: ./docs
          destination: ./_site

      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3

  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    needs: build
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

Critical configuration details (do NOT deviate from these):
- `source: ./docs` -- Jekyll content is in docs/, not repo root. Without this, the build would pick up README.md and Go files.
- `paths: ['docs/**', '.github/workflows/deploy-docs.yml']` -- Only triggers on docs changes, not every push to main.
- `workflow_dispatch` -- Allows manual trigger for testing without a docs change.
- `concurrency.group: "pages"` with `cancel-in-progress: false` -- Prevents deploy races, lets in-progress deploys finish.
- `permissions: id-token: write` -- Required for OIDC token exchange used by deploy-pages action. Without it, deployment fails with auth error.
- `environment.name: github-pages` -- Required for deploy-pages to work with GitHub's Pages infrastructure.

After creating the file, commit it and push to main. The push will trigger the workflow because `.github/workflows/deploy-docs.yml` is in the paths filter.

Then verify the workflow was triggered:
```bash
# Wait a few seconds for GitHub to register the push, then check
gh run list --workflow=deploy-docs.yml --limit=1
```

If the workflow is not triggered, manually trigger it:
```bash
gh workflow run deploy-docs.yml
```

Then wait for the run to complete:
```bash
gh run watch --exit-status
```
